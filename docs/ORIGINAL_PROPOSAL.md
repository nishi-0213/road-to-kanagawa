# 1. ゲーム概要

## 1.1 コンセプト

『Road to Kanagawa』は、ゾンビによって崩壊した日本を舞台に、関西から神奈川県・横浜を目指す、1〜4人協力型のサバイバルロードゲームである。

プレイヤーたちは1台の車で東へ移動し、各地でゾンビや生存者と遭遇する。

ステージ内ではリアルタイム戦闘を行いながら、チェストを探索して食料・燃料・素材などを回収する。

回収した物資を利用して武器や車を強化し、仲間と次のルートを多数決で決定しながら、最終目的地の横浜を目指す。

## 1.2 ゲームの特徴

- 1〜4人のオンライン協力プレイ
- 日本を東へ進むノード・エッジ式のルートマップ
- 多数決によるルート選択
- Phaserによるリアルタイムアクション戦闘
- ステージ内のチェスト探索による物資回収
- 食料・燃料・素材の管理
- 移動準備フェーズでのクラフト
- 全員準備完了によるフェーズ移行
- ゾンビを全滅させなくても脱出可能
- 都市ごとの特殊イベント
- 周回ごとに変化するイベントや物資

## 1.3 ゲームの目的

関西から出発し、食料・燃料・車の耐久力を維持しながら横浜へ到達し、最終イベントを突破する。

## 1.4 勝利条件

横浜の最終ステージで指定された目標を達成し、脱出条件を満たす。

## 1.5 敗北条件

- 食料が尽き、回復できなくなる
- 全プレイヤーが死亡する
- 車が修復不能な状態になる

燃料切れは即敗北とせず、脱出・復旧手段を設ける。

# 2. ゲーム全体の流れ

ゲームは以下の4フェーズを繰り返して進行する。

## 2.1 MAP：ルート選択

現在地から進める次のノードをマップ上に表示する。

各プレイヤーは進みたいルートへ投票する。

全員の投票が完了すると多数決でルートを決定する。

同票の場合は決選投票を行う。

ルートにはそれぞれ異なる特徴を設定する。

例：

- 山道：燃料消費が少ないが危険度が高い
- 国道：燃料消費が多いが危険度が低い
- 市街地：探索可能な物資が多いがゾンビも多い

## 2.2 PREPARATION：移動・準備

ルートが決定すると準備フェーズに移行する。

このフェーズでは、次の戦闘に向けて準備を行う。

可能な操作：

- 武器のクラフト
- 武器の強化
- 車の修理・強化
- インベントリ整理
- 装備変更
- 所持素材の確認
- 食料・燃料の確認

### 時間経過ルール

移動に実時間の制限は設けない。

プレイヤーが準備に時間をかけても、時間経過によって食料や燃料は減少しない。

資源はノード間の移動に応じて消費する。

### 準備完了ルール

各プレイヤーに「準備完了」ボタンを設ける。

全員が準備完了すると、自動的に戦闘フェーズへ移行する。

準備完了は全員が揃うまでは解除可能とする。

## 2.3 BATTLE：戦闘・探索

リアルタイムアクションステージに移行する。

プレイヤーは自由に移動し、ゾンビと戦いながら物資を探索する。

主な行動：

- 移動
- 攻撃
- ゾンビとの戦闘
- チェストの探索
- アイテムの回収
- 脱出地点への移動

### 重要な仕様

ステージをクリアしても、自動的に報酬は獲得しない。

**報酬となる物資は、ステージ内のチェストや探索対象から直接回収する。**

ゾンビをすべて倒す必要はない。

プレイヤーは探索を続けるか、危険を避けて脱出するかを判断する。

## 2.4 RESULT：ステージ終了・結果確認

脱出条件を満たすとステージ終了となる。

このフェーズでは以下を確認する。

- 生存プレイヤー
- 回収した物資
- 消費した資源
- 車の状態
- 現在の進行地点

ステージ終了による追加報酬は発生しない。

結果確認後、次のMAPフェーズに戻る。

# 3. マルチプレイ仕様

## 3.1 基本ルール

- 1ルーム最大4人
- 全員が同じ旅を進行する
- 1台の車を共有する
- 食料・燃料などの旅の資源はチームで共有する
- 戦闘中は各プレイヤーが独立して操作する
- ルート選択は多数決
- 準備フェーズ終了は全員の準備完了が条件

## 3.2 ルーム機能

トップ画面に以下を用意する。

- ルーム作成
- ルームコード入力
- ルーム参加
- 招待URLコピー

ルームコードはランダム生成する。

招待URLを受け取った友人は、ブラウザで開くだけで参加できる。

## 3.3 待機ロビー

実装予定の機能：

- プレイヤー名表示
- 参加人数表示
- 参加・退出通知
- ホスト表示
- ゲーム開始操作

## 3.4 切断・再接続

通信切断時の対応は今後実装する。

設計上は、再接続したプレイヤーが同じルームに復帰できる構造を目指す。

投票中・準備中・戦闘中の切断処理については詳細ルールを別途定める。

# 4. ワールドマップ

## 4.1 マップ構造

マップはノードとエッジで構成する。

ノードは到達地点を表す。

エッジはノード間の道路を表す。

プレイヤーは関西から横浜へ向かって東方向に進む。

## 4.2 ノード

ノードには以下の情報を持たせる。

- ノードID
- 名称
- 地域
- ステージ種別
- 危険度
- 接続先ノード
- イベント情報

## 4.3 エッジ

エッジには以下の情報を持たせる。

- 出発ノード
- 到着ノード
- 燃料消費量
- 食料消費量
- 危険度
- 特殊条件

## 4.4 主要地域

### 大阪・京都周辺

出発地点。

操作説明とゲームの基本システムを学ぶ。

### 名古屋周辺

大規模な生存者集団との遭遇。

交易・交渉・敵対勢力との戦闘など。

### 静岡周辺

燃料不足や道路封鎖などの危機。

資源管理とルート選択が重要になる。

### 横浜

最終目的地。

大規模な特殊イベントを用意し、最終目標を達成するとゲームクリア。

## 4.5 ローグライト要素

毎回のプレイで以下を変化させる。

- ノードイベント
- 敵の出現構成
- チェストの中身
- 回収可能な物資
- 生存者との遭遇
- 特殊イベントの結果

基本的な地理的進行方向は固定する。

# 5. 戦闘システム

## 5.1 基本形式

2D見下ろし型リアルタイムアクション。

Phaserを使用して描画・入力処理を行う。

## 5.2 操作

PCキーボードを使用する。

初期操作案：

| 操作 | キー |
|---|---|
| 移動 | WASD / 矢印キー |
| 攻撃 | Space |
| 調べる・チェストを開ける | E |
| インベントリ | I または Tab |
| メニュー | Esc |

操作方法は今後変更可能とする。

## 5.3 プレイヤー

プレイヤーは以下の状態を持つ。

- プレイヤーID
- 表示名
- 座標
- 移動方向
- HP
- 装備
- 所持品
- 生存状態

## 5.4 ゾンビ

最小版では、プレイヤーを追跡する単純なAIを実装する。

今後追加する要素：

- 複数種類のゾンビ
- 攻撃パターン
- 移動速度の違い
- 特殊能力
- 大型敵・ボス

## 5.5 戦闘判定

サーバー権威型を採用する。

プレイヤーは入力情報をサーバーへ送信する。

サーバーが以下を計算する。

- 移動
- 当たり判定
- 攻撃
- ダメージ
- HP
- 敵AI
- 死亡判定

クライアント側では描画と操作感の改善を担当する。

# 6. チェスト・ルートシステム

## 6.1 基本方針

物資獲得はゲームの中心的な仕組みとする。

ステージ終了時に自動報酬は付与しない。

## 6.2 チェスト

ステージ内にチェストを配置する。

プレイヤーはチェストへ近づき、Eキーで調べる。

チェストには食料・燃料・素材などを格納する。

最小版の仕様案：

- 1ステージ3個
- 1チェスト1回開封
- チェストの中身はランダム
- 開封状態は全員に同期
- 回収資源はチーム共有

## 6.3 ルートのリスクと報酬

危険な場所ほど貴重な物資を入手できる可能性を高める。

プレイヤーは以下を判断する。

- チェストをすべて探すか
- 必要な物資だけ回収するか
- HPが少ないので撤退するか
- 危険を冒して奥まで探索するか

## 6.4 二重取得防止

チェストの開封とアイテム取得はDurable Object側で確定する。

複数プレイヤーが同時に操作しても、同じ物資が二重取得されないようにする。

# 7. ステージ終了条件

## 7.1 通常ステージ

**生存しているプレイヤー全員が脱出地点に集合すると終了する。**

ゾンビを全滅させる必要はない。

未回収のチェストが残っていても脱出可能。

## 7.2 イベントステージ

固有の目標を達成した後、全員が脱出地点へ集合すると終了する。

イベント目標の例：

- 発電機の起動
- 生存者の救出
- ボスの撃破
- 特定アイテムの回収
- 防衛イベントの達成

## 7.3 全滅

全プレイヤーが死亡するとゲームオーバー。

## 7.4 未確定事項

- ダウン・蘇生システム
- 死亡プレイヤーの脱出判定
- 切断プレイヤーの扱い
- 脱出エリア内での敵の攻撃可否

これらは戦闘システム実装時に決定する。

# 8. 資源管理

## 8.1 基本資源

### 食料

旅を続けるために必要。

ノード間移動で消費する。

### 燃料

車の移動に必要。

選択したルートに応じて消費量が変化する。

### 素材

武器・車のクラフトや修理に使用する。

## 8.2 所持制限

所持可能な物資量には上限を設ける。

素材をクラフトによって別のアイテムに加工することで、所持品を整理・圧縮できる仕組みを検討する。

## 8.3 燃料切れ

燃料切れは即ゲームオーバーではない。

復旧方法の候補：

- 徒歩での移動
- 道路上の探索イベント
- 素材を利用した燃料クラフト

具体的な復旧ルールは今後決定する。

# 11. グラフィックス仕様

## 11.1 基本方針

**ゲーム用グラフィックスはPNG形式で管理する。**

キャラクター、ゾンビ、チェスト、アイテム、車、UI装飾、ロゴなどは透過PNGを基本とする。

背景もPNGで管理するが、背景全体を描画する画像は不透明でもよい。

## 11.2 制作方針

必要な画像を開発段階ごとに決定する。

画像制作前に以下を明示する。

- ファイル名
- 画像サイズ
- 視点
- アニメーション枚数
- 透過条件
- 表示サイズ
- 描画基準点

| ファイル名 | 推奨サイズ | 用途 |

| player.png | 64×64 | プレイヤー |

| title_background.png | 1920×1080 | タイトル背景 |

サイズは暫定仕様。

## 11.4 仮素材

# 15. 最小プレイ可能版（MVP）

最初の目標は、以下の体験を成立させること。

1. PCブラウザからゲームにアクセスする。
2. ルームを作成する。
3. 友人が招待URLから参加する。
4. 全員で同じステージに入る。
5. ゾンビと戦いながらチェストを探索する。
6. 食料・燃料・素材を回収する。
7. 全員が脱出地点に集合する。
8. ステージを終了する。
9. 次のルートを多数決で選ぶ。

このゲームループが面白いことを確認してから、クラフトや都市イベントを拡張する。

# 17. 開発上の基本方針

1. JavaScriptを使用する。
2. Phaserでゲーム画面を構築する。
3. Cloudflare WorkersとDurable Objectsを使用する。
4. WebSocketでリアルタイム同期する。
5. サーバーをゲーム状態の正とする。
6. 1ルームを1つのDurable Objectで管理する。
7. PCブラウザのみを対象とする。
8. グラフィックスは透過PNGを基本とする。
9. 素材が未完成でも仮表示で開発を進める。
10. GitHubでソースコードを管理する。
11. Cloudflareで公開し、URLだけで参加可能にする。
12. 機能は小さく実装し、段階ごとに動作確認する。
13. 既存の動作する機能を壊さずに拡張する。
14. 企画の面白さを検証してから機能を増やす。

# 18. Codexへの引き継ぎ指示

本書をRoad to Kanagawaの基本仕様書として扱う。

実装時は以下を優先する。

- まず既存プロジェクトのファイル構成と実装状況を確認する。
- 動作済みの機能を維持する。
- 一度に大量の機能を追加しない。
- フェーズごとに開発・テストする。
- サーバー側で重要なゲーム判定を行う。
- クライアントから送信される値を信用せず検証する。
- グラフィックスが必要になったら、制作するPNGの仕様を開発者に提示する。
- 画像が存在しない場合は仮表示で対応する。
- 未決定のゲーム仕様を勝手に確定せず、必要な場合は確認する。
- ローカル実行とCloudflare公開の両方を考慮する。
- 最終的に友人がURLから参加できる状態を目指す。
