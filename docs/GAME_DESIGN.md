# 現行仕様

2026-10-24（日本時間）。最新のユーザー指示に基づき旧ゲームを初期化。

- Phaserのゲームウィンドウをブラウザ表示領域いっぱいに配置し、リサイズに追従。
- HTMLは入室操作のみ：「1人で遊ぶ」「ルーム作成」「ルームコード入力欄」「ルームコードを入力して入室」。入室後はHTMLを非表示。
- 1人プレイではAPI・WebSocketを利用しない。
- 協力プレイは最大4人。Workersでルームを作成、1ルーム1 Durable Object、WebSocketで人数を共有。休止対応のWebSocket APIを使用。
- Phaser内にルームコード・人数・招待URLコピー・退出を表示。準備完了ボタンとフェーズ遷移を実装。戦闘ではプレイヤー移動と脱出を実装。敵・収集は未実装。
- ここでいうログインはプレイ方法・ルームの選択。アカウント認証は未実装。12文字コードは招待用。
- GitHubへ登録しCloudflare Workersで公開。静的ファイルとAPIを同じURLで配信。

## 準備・戦闘フェーズ

- 入室時に左上へ「準備フェーズ」と表示する。
- 右側に上から下へ、現在の参加人数分の準備完了ボタンを並べる。自分のボタンだけ操作でき、他の人の状態は全員へ共有する。
- 全員がそろうまでは準備完了の取消が可能。新しい参加者は未準備で入室する。
- 全員が準備完了になると左上を「戦闘フェーズ」に切り替え、準備ボタンを消す。戦闘の内容は以下のタイルマップ・移動・脱出を実装。
- 協力プレイはDurable Objectが接続者ごとの準備状態を管理・検証し、全員準備を確定する。WebSocket休止後も準備状態とフェーズを維持する。
- 1人プレイはローカル処理のみで、APIやWebSocketを使用しない。「ルーム作成」で作るオンラインルームは1〜4人で利用可能。
- 戦闘開始後の途中参加は拒否する。退出した人は準備判定から除外し、残った全員が準備完了なら戦闘へ進む。全員退出すると準備フェーズへ戻る。


## 戦闘マップ・移動・脱出

- 1マス32×32pxの地面を敷き詰める。戦闘ごとに横×縦30×40、50×25、40×30、20×60マスから等確率で選ぶ。
- 1〜4人全員が左下の2×2マス付近から開始。カメラは自分を追従し、マップ外へは移動できない。
- WASDで移動。通常速度は仮設定160px/秒。斜め移動は正規化する。
- Shift＋移動で速度1.5倍。スタミナは満タンから4秒で0、ダッシュしていない間は空から6秒で全回復。静止中は消費しない。枯渇後は全回復まで再ダッシュを待つ。HUDにゲージを表示。
- 右上に横2×縦3マスの脱出ゾーン。判定はプレイヤー中心がゾーン内にあるかで行う。PhaserのGlow FXを使用し、0人で黄色、1人以上で黄緑、全員で青色。Canvasレンダラーでは色付きエリアを表示する。
- 全員が入るとゾーン上の小さなバーが進行し、連続3秒で準備フェーズへ戻る。1人プレイは1人で成立。誰かが出ると0へリセット。
- 脱出後は全員を未準備に戻す。次の全員準備完了で新しいランダムマップと満タンのスタミナから再開。
- 協力プレイはサーバー20Hzで移動・スタミナ・脱出を判定し、入力のみ受け付ける。入力が250ms途絶えると停止。準備フェーズではWebSocket休止を利用し、戦闘中は更新タイマーを動かす。
- プレイヤーは32×32表示。添付画像の元PNGが実行環境に未提供のため、現時点では仮の白い人物を表示。`client/assets/player.png`に元PNGを置くと自動的に使用する。
